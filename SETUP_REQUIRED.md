# Activation checklist

The local application, offline demo, tests, guides, and disabled workflow templates are implemented. **No live Sheet, Gmail send, recurring run, or automated company source has been verified or enabled.** This file records the remaining activation steps rather than implying that absent credentials passed a live test.

1. **Google Sheet:** create an invite-only spreadsheet and enable the Sheets API in your Google project. Configure `GOOGLE_SHEET_ID` and either local ADC, a private service-account credential, or tightly scoped Workload Identity Federation for the private runtime repository and main branch. Share the Sheet with that service account. Run `scripts/setup_google.py --plan` first, then follow [setup](docs/setup.md). The CLI bootstraps an existing empty Sheet; it does not silently create or change sharing on Drive files.
2. **Private profile:** configure `PRIVATE_PROFILE_PATH` or `PRIVATE_PROFILE_YAML_B64` with approved evidence, preferences, and company tiers. Supply a stable high-entropy `PRIVACY_HMAC_KEY` and exactly one `ALERT_RECIPIENT_EMAIL`. Local private configuration is intentionally ignored by Git. Never upload it as an issue, artifact, or code change. After initial bootstrap the Sheet owns this data.
3. **Initialize and verify:** run `uv run career-radar bootstrap-sheet`, `uv run career-radar doctor --require sheet --verify-write`, and `uv run career-radar sheets verify`. Bootstrap preserves nonempty user tables. Inspect all tabs and protections in the actual Sheet before unattended use. The write probe changes and restores one system marker.
4. **Approve sources:** complete current policy evidence and review for specific official sources in the Sheet. All 280 bootstrap rows start non-collecting. Three offer manual/native-alert routes; 277 await validation. Run `uv run career-radar source check --all`, then a dry scan with the approved source. Repeat the same input to verify idempotency against the real Sheet. See [adding a source](docs/adding-a-source.md).
5. **Owner email:** use the separate send OAuth client and exact `gmail.send` scope. The optional read grant uses a separate credential and `gmail.readonly`; live mailbox ingestion is deferred. Do not use a testing-mode expiring grant for unattended OAuth. Run the plan/verification helpers described in [alert setup](docs/alert-setup.md). Perform at most one explicitly requested owner test-email attempt and inspect `SENT`, `FAILED`, or `AMBIGUOUS`; an ambiguous send must not be retried automatically. Third-party sending does not exist.
6. **GitHub delivery:** the owner approved publication on 2026-09-14. The [public code repository](https://github.com/balajik10/career-command-center) and [private runtime repository](https://github.com/balajik10/career-command-center-runtime) have been created. Runtime tracking and scheduling are explicitly disabled. Pin both runtime references to the exact reviewed public commit; check the final delivery record for its CI result. See [runtime template](runtime-template/README.md).
7. **Scheduling:** install the named private secrets with `scripts/configure_github.sh --repo balajik10/career-command-center-runtime --plan` before `--apply`. Keep `TRACKER_ENABLED=false` and `SCHEDULER=disabled` until public CI, real Sheet verification, source dry-run, owner delivery verification, and the current account-wide cost guard pass. Run `doctor --require scheduled --verify-write` before enablement. No credentials are inherited into the public repository. The local scheduler is available if private Actions allowance is insufficient.

Repository and Sheet URLs should be recorded only after those resources actually exist. Live integration failures belong in private run records with redacted public summaries. Review [privacy](docs/privacy.md), [operations](docs/operations.md), and [troubleshooting](docs/troubleshooting.md) before activation.
